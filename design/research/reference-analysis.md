# SHADOW 市场 · 5 参考站布局研究与现站诊断

> 版本：v1（2026-11-01）｜作者：design-research｜用途：支撑 `design/DESIGN-BRIEF.md` 的「个人工作台优先 + 右侧栏进市场」重设计。
> 截图：`design/references/`（仅内部研究，不进产品页面，不再分发）｜度量原始值：`design/research/layout-metrics.md`。
> 视口 1440×900、DSF 1、Edge headless + 本机代理；尺寸由 Playwright `evaluate` 读 computed style / boundingRect 得出。

---

## 0. 结论摘要（先看这 8 条）

1. **5 个站的内容容器只有 1–2 种宽度**（GitHub 1280 / Linear 1344 / Vercel 1392 / Stripe 1232 / Raycast 1204）。现站有 **6 种**（928/896/800/1232/1280/844）→ 对齐感崩塌是「乱」的第一来源。
2. **右栏（320 宽）不是主任务区**：GitHub Explore 右栏=Trending developers，个人页右栏=People/Sponsoring/Top languages/Topics，Linear 属性栏 286，Stripe 产品页右栏=计划详情。「市场/发现」天生属于右栏——brief 把「进入市场」放右栏，逻辑成立；但右栏要**少而重**。
3. **字号要「少而陡」**：GitHub 12/14/16/20/24，Linear 12/13/15/24/48/64，Vercel 14/16/24/56/64。现站渲染 **13 种**字号、80.1% 的文本 ≤12.5px、11px 用了 106 处 → 「平」且「小」。
4. **边框与胶囊是廉价感的放大器**：Vercel 全页只有 **3** 个带边框元素；现站桌面 **145** 个、移动 **140** 个。现站首页 **98** 个 pill、分布在 41 个 y 行（移动 49 行）。
5. **颜色纪律**：Vercel 6 色 0 强调；Raycast 4 灰 + 1 黑底；GitHub 1 个 UI 强调色（#0969da）；现站 16 渲染色 + 两套近似灰（#57606a 316 处 / #59636e 137 处）+ 两族强调（橙 #c2410c 56 处 + 绿 #116329 30 处）。
6. **节奏公式**：区块间距（32–64，营销页 128–256）≫ 卡片间距（16–24）≫ 卡内 padding（16–24）。现站反过来：列表卡间距 **8px**、区块 32、侧栏组间 21。
7. **现站「首屏没有内容」是可量化的**：390 宽下第一张资源卡 y=**698**（屏高 83%），前面塞了 h1、2 按钮、86px 通知条、7 分类、21 标签、4 类型、4 快捷入口；底部 53px bottom-nav 还压住内容。
8. **现站桌面缺右栏**：首页 272+928 两栏（右边界 x=1336，余 104px 空白）；详情页却有 904+296 三栏 → 同一产品内部信息架构不一致，用户找不到「市场在哪」。

## 1. 方法与口径

- **工具**：Playwright（`playwright-core` + 系统 Edge），1440×900、DSF 1、`networkidle` 或 5s 兜底、点击 Accept/关闭 cookie 与订阅弹层；每站另采 `page.evaluate` 度量。390 宽移动截图 2 张（GitHub 个人页、Linear）。
- **GitHub 限制**：无登录态，**登录后 dashboard 不可得**（`github.com/dashboard` 重定向到登录）。按任务允许的降级方案，用 `github.com/explore`（公开发现页）+ `github.com/vercel`（公开组织个人页，含完整「身份头 + tab + 主列 + 右栏」）代替，并在结论中标注。
- **度量口径**：「渲染颜色数」= 可见元素 `color/background/border` 去重（忽略透明度 <8% 的色值与透明底）；「带边框元素」= 可见且有非 0 边框宽度/样式的元素数；「pill」= 可见元素圆角 ≥90px 且高 16–36px；容器宽度按 4px 归并取众数。营销页含产品截图的，颜色数会偏高，分析时以「UI 自身色板」为准（会注明）。
- **现站**：本地 `node market/serve.mjs --port 18980` 只读截图（未改 `market/**`）；诊断同时引用 `release/evidence-market/shots/` 既有截图。

## 2. 逐站分析

### 2.1 GitHub（`github-explore.png` / `github-profile.png` / `github-profile-390.png`）

**结构**：营销 header 68 → 二级 tab 55 → 内容 1280。Explore 是 3 列 320/640/320（左列 320 在未登录态**为空**，实际有效=主列 640 + 右栏 320）；个人页是 2 列 **960 + 320**，且叠了「身份头 156 + tab 48」两层。
**导航组织**：全局营销 nav（Products/Developers/…）与产品 nav（Explore/Topics/Trending）分离；个人页 tab 6 项（Overview/Repositories/Projects/Packages/People/Sponsoring）带计数；入口不重复。
**容器与卡片**：Borders-as-structure——1px `#d1d9e0` + 6px 圆角 + 16px padding 的 Box；个人页 Pinned 2×456（视觉间距 16）；右栏块之间用 1px 细分隔线 + 24px 留白，**不套卡**。
**字体**：body 14/21、meta 12/18（139 处 12/500）、标题 20/600、个人页 h1 24/600；字重只用 400/500/600。**字号只有 5 档**。
**颜色**：22 种渲染色，但 UI 只有 #1f2328（文字）、#59636e（次文字）、#0969da（唯一强调/链接）、#d1d9e0（边框）、#f6f8fa（浅面）。彩虹色只出现在语言 dot（非 UI）。
**留白**：16px 基准；页边 80；右栏内容宽 288（320−32 padding）。
**右栏**：Explore=Trending developers 列表 + 「See more」；个人页=People（35px 头像 5×4）/Sponsoring/Top languages/Most used topics（chip）。**全部是「辅助了解」，不是主任务**。
**可借鉴 3 条**：①「身份头 + tab + 主列 + 右栏」四段式就是个人工作台的骨架（我们的 header 64 + 问候 + 数据 tile 可对应身份头，tabs→不做，主列+右栏照搬比例）；②主列宽：右栏 = 3:1（960:320），现站可 744:320 同比例；③右栏用「标题 + 纯列表 + See more」的轻结构，比堆 4 张卡更安静。
**不抄**：灰色密度（三种灰、12px 铺满）、268 个带边框元素、营销黑头 + 白页的高对比、仓库卡的 12px 小字。

### 2.2 Linear（`linear.png` / `linear-390.png`）

**结构**：fixed header 73（padding 0 32）→ 内容最大宽 1344；产品演示框 1320 = 左侧栏 232 + 主面板 1072，面板内再分 662 + 属性栏 286（就是「导航 / 主内容 / 右栏」的桌面应用版）。
**导航组织**：营销 nav 6 项 + 右侧 Log in / Sign up 两枚 pill；应用演示里是 Workspace/Favorites 分组（12px/510 组标题 + 13px/510 项）。
**容器与卡片**：几乎无边框（129 个带边框元素，多为演示 UI 内的 1px ring）；卡片靠 `#0f1011/#161718` 表面色差 + `0 0 0 1px inset` 微光；按钮全 pill（82 处 9999），输入/卡片 8px、12px。
**字体**：h1 64/510/lh64/ls−1.41；h2 48/510；h3 20/590；正文 15/24/ls−0.165；UI 13/510；micro 12/510。**显示字与 UI 字之间没有中间碎档**。
**颜色**：背景 3 层（#08090a / #0f1011 / #161718），文字 4 级（#f7f8f8/#d0d6e0/#8a8f98/#62666d）；UI 强调色只有 1 个（产品内的彩色标签是演示截图，不计入设计语言）。
**留白**：hero 只留 nav，h1 前约 150px 空白；区块间距 160–270（hero→产品演示框 581）；组件内 8–12。
**右栏**：应用内属性栏 286，sticky，承载「状态/属性/评论」——**上下文，不是导航**。
**可借鉴 3 条**：①暗色层级 = 3 个背景面 + 1 条 hairline，靠明度差而不是边框；②数字级：display 64 / section 48 / 20 / body 15 / UI 13 / 12，**只有 6 档**，与 brief 的 34/28/22/17/14/13/12 同思路；③桌面 3 区 232/内容/286 与 brief 的 248/主列/320 同一比例族。
**不抄**：产品 UI 的复杂交互与演示截图密度；把彩色标签当强调（我们只允许琥珀）。

### 2.3 Vercel（`vercel.png`，附 1440 首屏）

**结构**：sticky header **64**（正好等于 brief 的 header 高度）→ 内容 1392（页边 24）；hero 是 3 栏：左文案 444 / 中央图形 / 右侧注解 364。
**导航组织**：一级 5 项 + 右侧 3 个按钮，无二级；全部内容靠页面滚动分区（区块间距 256）。
**容器与卡片**：**全页 3 个带边框元素、6 张卡、1 种阴影**；卡靠留白与 6/20px 圆角区分；功能块是 921 + 333 的非对称 2 栏（gap 20）。
**字体**：h1 64/400/lh64/**ls−3.84（−6%）**；h2 56/450/ls−3.36；正 16/450；UI 14/400。字重 400/450/500。
**颜色**：**6 种**（#171717/#4d4d4d/#8f8f8f/#fff/#fafafa/#666）、**0 强调色**、1 个阴影。品牌感=字距+留白。
**留白**：页边 24，hero 728 高只放 3 样东西；区块间距 256；卡内 20–24。
**右栏**：无（营销页）。
**可借鉴 3 条**：①「无边框 + 大留白 + 紧字距大标题」能靠排版建立质感——brief 的 display 34 也可用 −0.02em；②单色纪律：预算 6 色 0 强调，证明「暖黑 + 琥珀」不需要第三种色也能好看；③页边 24–40 就够，内容不必压到 1440 满宽。
**不抄**：营销页首屏只有一句话的低密度（工具型工作台首屏必须承载数据/动作）；256px 级区块间距在 900 高屏上浪费。

### 2.4 Stripe（`stripe.png` / `stripe-payments.png`）

**结构**：header **76** + 产品子导航 **56**（Payments/Overview/Features/…）→ 产品页内容 1080（x=180，页边 180）；首页容器 1232（页边 104）。
**导航组织**：全局 header + 「产品内子导航」两层；子导航是同级页面切换，不重复全局 nav。
**容器与卡片**：首页 bento 816 + 400（gap 16）、section-row gap 64；产品页 hero = 左文案 + 右产品 UI 卡（卡内再分 2 栏）；圆角只有 4/6px（8 档），几乎不用阴影（3 档）。
**字体**：首页 h1 48/300/lh55/ls−0.96、h2 32/300、h3 26/300、正 16/300/lh22.4；产品页 display **56/500/lh68/ls−1.12**、分区标题 38/500、正文 15/300（134 处）+ 14/400（87）。**300 字重是 Stripe 的「编辑感」，但中文小字太细会糊**。
**颜色**：首页 34 色（主强调紫 #533afd 501 处）；产品页 69 色（插画/渐变多）。**颜色不是我们学的东西**。
**留白**：8px 基准 + 固定 270px 列导引线；区段内 24/32，区段间 64。
**右栏**：首页无；产品页右栏是「计划详情」卡——把决策信息（价格/权益/操作）放右，**正文永远在左**。
**可借鉴 3 条**：①「全局 header + 产品子导航」两层结构，正好可用于「工作台/市场/详情」的跨区切换；②内容秩序 = 一种内容宽度（1080）+ 8px 基准 + 固定列导引，而非多种容器；③hero/详情用「左解释 + 右实体卡（下载/导入/统计）」——brief 的详情右栏就是 Stripe 产品页的右卡。
**不抄**：紫蓝绿渐变插画（违反 brief 反模板）；300 字重小字（中文可读性差，我们 400/500）；4–6px 小圆角（与 brief 卡片 16 冲突）。

### 2.5 Raycast（`raycast.png`）

**结构**：浮动圆角顶栏（约 1200×68，距顶 20）→ 内容 1204/1184；扩展卡 360×536，分区 320 + 679（gap 85）。
**导航组织**：单层 8 项 + Log in / Download 两枚；命令面板（⌘K）是产品入口，不是页面导航。
**容器与卡片**：卡片有「实体感」：1 种材质模式（`0 0 0 1px inset` + 24–32px 软阴影 + 11–20px 圆角）重复使用；卡内 24，卡间 16–24。
**字体**：h1 64/600/lh70；分区 32/500；正文 18/400；UI 14/500/ls 0.2px；小字 12。字重 400/500/600。
**颜色**：22 色但 4 灰（#6a6b6c/#9c9c9d/#434345/#e6e6e6）+ 白 + 黑底 #08090c；彩色只出现在用户图标/产品图 → **暗色质感的重点是「灰阶层次 + 一种材质」，不是多彩**。
**留白**：hero 只放标题/副标/一个按钮；卡内 24。
**右栏**：无。
**可借鉴 3 条**：①「1 种卡片材质」重复到底（brief 的卡片阴影就应只有 1 种）；②暗色下强调色只出现在 hero 光效/图标，UI 本身几乎无彩；③⌘K/命令面板式入口适合我们 header 的搜索（已有 `/` 快捷键，可升级为 ⌘K）。
**不抄**：27 种圆角、27 种阴影的「材质大杂烩」（截图里的产品 UI 更花）；大面积红色光效；桌面客户端专属交互。

## 3. 横向总结：5 站共性的 7 条「美感来源」

1. **容器单一定义**：每站正文容器 1–2 种宽度，页面其余元素都对齐到它（GitHub 1280 / Linear 1344 / Stripe 1080+1232 / Raycast 1204）。→ 一致的对齐感来源；**现站 6 种必删到 1 种**。
2. **字号「少而陡」**：正文 14–16 是绝对主力，meta 12–13，display 24–64；没有 11.5/12.5 这类碎档。→ 可读性 + 层级。
3. **颜色预算 6–22，强调色 ≤1（Vercel 0、GitHub 1、Stripe 1、Linear 1、Raycast 1）**。中性 3–4 层 + 一个强调是共同配方。
4. **留白是层级**：区块间距（32–256）≫ 卡片间距（16–24）≫ 卡内（16–24）的 2 倍差；组与组之间的空白比组内大 1 个数量级，读者才能「分段」。
5. **边框只给可交互物**：Vercel 3 个、GitHub 79（个人页）个；卡片靠表面色差 + 阴影分层。→ 「无边框卡片」方向被 4/5 站验证。
6. **排版节奏**：display 负字距（−0.02~−0.06em）+ 紧行高（1.0–1.1）；正文行高 1.5–1.7；小字/按钮用 +0.02em 正字距。→ 大标题「贵」的秘诀。
7. **右栏的固定角色 = 上下文/发现/决策**：GitHub 右栏 Trending/People，Linear 属性栏，Stripe 计划详情。主任务永在中列，右栏只放「帮助判断」的信息。→ brief 的「右栏进市场」符合这一角色分工，但右栏必须安静、少卡、sticky。

## 4. 现站诊断：10 条「杂、乱」的具体原因（每条带证据与改法）

1. **容器宽度 6 套，主列两套**。首页 272+928、详情 904+296、容器 928/896/800/1232/1280/844 并存。→ **改法**：单一容器 1360（1440−2×40），grid `248 / minmax(0,1fr) / 320`，gap 24，所有页面共用；卡片只允许 2 种宽度（主列满宽、网格半宽）。
2. **字号碎档、正文太小**。渲染 13 种字号（首页）/16 种（详情，含 12.47px、14.5px）；80.1% 文本 ≤12.5px；11px 出现 106 处；h1 只有 24px。→ **改法**：7 档 token（34/28/22/17/14/13/12），正文 14/22；11px 只允许 uppercase 标签（ls .06em）；出现 `12.47/11.5/13.5` 视为 bug。
3. **胶囊/标签滥用**。首页 98 个 pill、112 处 999px 圆角、分布在 41 个 y 行；标签云 21 个标签全量铺 3 行；移动端 49 行 pill。→ **改法**：pill 预算 ≤12/屏；标签只在资源卡底部（≤4）与筛选器；热门标签右栏 5 个；删除标签云。
4. **盒子过载**：145 个带边框元素 + 142 个带背景块（桌面）；详情右栏 6 张带边框卡。对比 Vercel 全页 3 个。→ **改法**：卡片无边框（bg-2 + 1 种阴影）；边框只给输入框/控件/tab 下划线；每屏带边框元素 ≤30，写进验收。
5. **导航与入口重复**：header 10 个可点项、侧栏 4 组 777px 高、footer 4 列 11 链接、移动端 bottom-nav 5 项 + 快捷区；「一键导入说明」同时出现在 header 右侧、侧栏、移动快捷区；搜索在桌面 header 与移动独立行重复。→ **改法**：导航唯一来源=左栏 7 项；header 只留 logo/搜索/积分/主题/语言/头像；说明类统一进右栏卡与详情折叠；footer 只留法务/技术 2 列。
6. **强调色两族 + 两套近似灰**：橙 #c2410c（56 处）+ 绿 #116329（30 处）+ 资源封面色（绿/紫/蓝）；文字灰 #57606a（316）与 #59636e（137）几乎同色各用一套。→ **改法**：强调=琥珀 1 个 + success 只给「免费/成功」；灰阶 3 个（text/text-2/text-3）；封面色只允许琥珀 5 档；渲染色 ≤14。
7. **桌面没有右栏（市场入口没有家）**：首页 2 栏，右边界 x=1336、余 104px 空白；右栏 token `--aside-w:296px` 只在详情使用。→ **改法**：全站桌面 3 栏，右栏 320 sticky（top 88）；首页右栏第一卡=「进入市场」大卡（唯一渐变面），详情右栏=下载导入/统计/许可；收藏沿用工作台右栏。
8. **首屏被 chrome 吃掉（移动端最严重）**：390 宽第一张资源卡 y=**698**/844；通知条 86px；分类 2 行 + 标签 3 行 + 类型 2 行 + 快捷 2 行；bottom-nav 压住卡片。桌面通知条 1232×46 也在 y=171。→ **改法**：移动端首屏 = 问候 + 1 主 CTA + 继续上次 + 2 张推荐卡（第一张卡 y≤480）；通知改 12px 单行（可点开折叠）或进右栏/详情；标签云与快捷重复区删除。
9. **首页不是「我的」，且内容重复**：H1=「探索市场」，无数据/无继续上次/无动态；10 个卡片实例只对应 7 条资源（推荐 3 + 全部资源 7 两段列表，另有「最新更新」行列表）；详情页 5 个并列动作 + 按钮下方两行长文字说明。→ **改法**：`#/` 个人工作台（问候 + 4 tile + 继续上次 + 2×2 推荐 + 动态时间线），市场移 `#/market`；详情 1 主 CTA + 2 次动作 + 溢出菜单，说明进右栏折叠。
10. **层级语义错误 + 节奏不均**：详情页有 **2 个 H1**（Hero 26px 里塞 5 个徽标 + README 24px）；列表卡间距 8px、区块 32px、侧栏组间 21px，节奏反了；移动端详情吸底操作条 46px + bottom-nav 53px 叠成 99px（屏高 11.7%）。→ **改法**：H1 只出现一次（徽标移到 H1 下 meta 行，≤3 个）；卡片间距 16/24、区块 32–48；移动端详情「吸底操作条替换 bottom-nav」二选一，不叠加。

### 5.5 对 brief 的 3 处方向性修正

1. **右栏 4 卡 → 3 块**：把「平台动态」并入工作台主区「最近动态」时间线（避免右栏又变成 4 个盒子）；右栏 = 进入市场大卡 + 热门标签（5 个）+ 合规一行。GitHub 个人页右栏 4 段之所以不吵，是因为它们**没有卡框**——若我们必须保留 4 张卡，则改为「1 张带底色大卡 + 3 个无边框文本块 + 细分隔线」。
2. **「进入市场」是跨区跳转，必须给视觉特权但只能给一处**：全站唯一渐变面+唯一「箭头」大卡；市场页里镜像成「进入工作台」卡（同样位置、同样尺寸，内容对调）——这是 Stripe 产品页右卡「决策信息」的做法。
